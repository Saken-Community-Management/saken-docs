# Secrets & environment

A reference for every secret and environment variable across the three repos, and where
each one lives.

## Web app (`saken`)

Set in **Vercel → Settings → Environment Variables** (Production, Preview, Development) and,
locally, in `.env.local` (gitignored). The app reads only these:

| Var | Scope | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | public | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | public | anon/publishable key — sent to the browser |
| `SUPABASE_SERVICE_ROLE_KEY` | **server-only** | RLS-bypass key for the narrow service-role operations |
| `NEXT_PUBLIC_PHONE_AUTH_ENABLED` | public | feature flag — reveal the phone/WhatsApp OTP option |

<Callout type="error">
**Never expose the service-role key**

`SUPABASE_SERVICE_ROLE_KEY` **bypasses RLS**. It must never be a `NEXT_PUBLIC_*` variable
and must never reach the browser. The publishable anon key may be either the legacy `eyJ…`
anon JWT or the newer `sb_publishable_…` key — but the service-role key is a different,
secret value.
</Callout>

## CI / GitHub Actions (`saken`)

Set in **Repo → Settings → Secrets and variables → Actions** for the migration pipeline:

| Secret | Purpose |
| --- | --- |
| `SUPABASE_ACCESS_TOKEN` | a personal access token from supabase.com |
| `SUPABASE_DB_PASSWORD` | the `saken` project DB password |
| `SUPABASE_PROJECT_ID` | `zrjeehvlvhjaafhkxgsw` |

Plus the **`production` environment** with required reviewers (the migration approval gate),
and the `MIGRATIONS_PIPELINE_READY` variable.

## Edge function (`send-otp`)

| Secret | Purpose |
| --- | --- |
| `SMS_API_KEY` | the SMS provider key for sending OTPs |
| `HOOK_SECRET` | verifies the auth-hook payload signature |

<Callout type="error">
**`HOOK_SECRET` must be set**

If `HOOK_SECRET` is unset, the `send-otp` function **skips signature verification** and
even falls back to an unverified JWT decode on failure (audit L-S1) — an SMS-pump / toll-
fraud vector. Set it and **fail closed** before relying on phone auth.
</Callout>

## Backend (`saken-server`)

`.env` (copied from `.env.example`), pointing at the **same Supabase project** as the web
app:

| Var | Purpose |
| --- | --- |
| `SUPABASE_URL` | project URL |
| `SUPABASE_ANON_KEY` | per-request RLS client + token validation |
| `SUPABASE_SERVICE_ROLE_KEY` | narrow service-role operations |
| `PORT` | HTTP port (default `4000`) |
| `CORS_ORIGINS` | allowlist, or `*` |
| `PUBLIC_API_URL` | absolute-link base in responses |

## MCP server (`saken-mcp`)

| Var | Purpose |
| --- | --- |
| `SAKEN_API_URL` | base URL of `saken-server` |
| `SAKEN_ACCESS_TOKEN` | a user's Supabase access token; scopes everything the MCP server can do |

## Where production values are managed

| Surface | Source of truth |
| --- | --- |
| Web app runtime | Vercel env vars |
| Migration pipeline | GitHub Actions secrets + the `production` environment |
| Supabase Auth providers (Google/Twilio) | Supabase Dashboard → Authentication → Providers |
| Local dev | `.env.local` / `.env` (gitignored) |
